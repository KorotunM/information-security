# Криптографический практикум

Desktop GUI-приложение на Python для лабораторного практикума по криптографии и теории передачи информации.  
Проект объединяет несколько учебных модулей в одном окне с общей главной страницей и навигацией через `QStackedWidget`.

## Какие алгоритмы реализованы

1. RSA
2. Классический аддитивный рюкзак (Merkle-Hellman, АВКР)
3. Классический мультипликативный рюкзак (МВКР)
4. Обобщённый аддитивный рюкзак (GAKP / GAKR)
5. Обобщённый мультипликативный рюкзак (GMKP / GMKR)
6. Код Хэмминга `[7,4]` для обнаружения и исправления одной ошибки

## Теоретическая база

В проект заложены следующие идеи:

- общая модель криптосистемы: пространство открытых сообщений, пространство ключей, пространство шифртекстов, алгоритмы шифрования и дешифрования;
- RSA: модульная арифметика, функция Эйлера, обратный элемент по модулю, блочное шифрование `m < n`;
- рюкзачные схемы: задача subset sum, сверхвозрастающие последовательности, модульное маскирование, жадное восстановление;
- мультипликативные рюкзаки: приватные простые множители, открытый рюкзак из корней сравнения `b_i^s ≡ w_i (mod m)`, восстановление через произведение;
- обобщённые рюкзаки: коэффициенты `0..B-1`, кодирование символов выбранного алфавита цифрами по основанию `B`;
- Hamming `[7,4]`: проверочные биты, синдром, кодовое расстояние `3`, исправление одной ошибки.

## Какие учебные допущения приняты

### Входной алфавит сообщений

- Для текстовых сообщений в рюкзачных модулях принят единый фиксированный алфавит:
  `abcdefghijklmnopqrstuvwxyz `
- Выбор режима сообщения и выбор алфавита в интерфейсе убраны.
- Сообщения, содержащие другие символы, отклоняются валидатором.

### RSA

- Реализация учебная, а не промышленная.
- Используются небольшие простые числа.
- Нет схем паддинга вроде OAEP.
- Ввод сообщения также ограничен алфавитом `abcdefghijklmnopqrstuvwxyz `.
- Для текста используется прямое кодирование:
  `a→0, b→1, ..., z→25, пробел→26`.
- Множество числовых эквивалентов:
  `Q={0,1,2,…,25,26}`.
- Каждый символ шифруется как число `m` по формуле `c = m^e mod n`.

### Классический аддитивный рюкзак

- Используется классическая схема Merkle-Hellman.
- Закрытый ключ: сверхвозрастающая последовательность `w`.
- Открытый ключ: `b_i = a * w_i mod m`.
- Для текста сначала используется кодирование
  `a→0, b→1, ..., z→25, пробел→26`, то есть `Q={0,1,2,…,25,26}`.
- Затем каждый элемент `Q` представляется фиксированным 5-битным двоичным словом.
- Уже полученный двоичный вектор подаётся в классический рюкзак как коэффициенты `0/1`.

### Классический мультипликативный рюкзак

- В качестве учебной постановки выбран мультипликативный рюкзак, где вместо суммы используется произведение.
- Закрытый ключ: набор простых чисел `W = (w_1, ..., w_n)` и секретный показатель `s`.
- Выбирается простой модуль `m`, причём `m > ∏ w_i^x_i` для допустимых коэффициентов.
- Открытый ключ строится из значений `b_i`, для которых выполняется `b_i^s ≡ w_i (mod m)`.
- Шифртекстом является произведение `c = ∏ b_i^x_i mod m`.
- Дешифрование идёт через вычисление `u = c^s mod m`, после чего число `u` раскладывается по приватным простым множителям.
- Для текста сначала используется кодирование
  `a→0, b→1, ..., z→25, пробел→26`, то есть `Q={0,1,2,…,25,26}`.
- Затем каждый элемент `Q` представляется фиксированным 5-битным двоичным словом.
- Уже этот двоичный вектор шифруется классическим мультипликативным рюкзаком.

### Обобщённый аддитивный рюкзак

- Используется параметр `p`, задающий диапазон коэффициентов `x_i ∈ {0,1,…,p-1}`.
- Для текста сначала применяется кодирование
  `a→0, b→1, ..., z→25, пробел→26`, то есть `Q={0,1,2,…,25,26}`.
- Затем каждый символ представляется в виде `p`-ичного блока фиксированной длины `n`.
- Закрытый рюкзак `W = (w_1, ..., w_n)` должен быть обобщённо сверхвозрастающим:
  `w_i > (p - 1) * Σ_{j < i} w_j`.
- Модуль выбирается так, чтобы `m > (p - 1) * Σ w_i`.
- Открытый рюкзак строится по формуле `b_i = a * w_i mod m`.
- Шифрование блока: `c = Σ x_i b_i`.
- Дешифрование: `c' = a^(-1) * c mod m`, затем жадное восстановление коэффициентов по закрытому рюкзаку.
- В демонстрационном примере используется `p = 3`, `n = 4`, `W = (2, 5, 16, 50)`, `m = 149`, `a = 31` для слова `hi`.

### Обобщённый мультипликативный рюкзак

- Используется параметр `p`, задающий диапазон коэффициентов `x_i ∈ {0,1,…,p-1}`.
- Для текста сначала применяется кодирование
  `a→0, b→1, ..., z→25, пробел→26`, то есть `Q={0,1,2,…,25,26}`.
- Затем каждый символ представляется в виде `p`-ичного блока фиксированной длины `n`.
- Закрытый рюкзак `W = (w_1, ..., w_n)` состоит из простых чисел.
- Модуль выбирается так, чтобы `m > ∏ w_i^(p-1)`.
- Открытый рюкзак строится по условию `b_i^s ≡ w_i (mod m)`.
- Шифрование блока: `c = ∏ b_i^x_i mod m`.
- Дешифрование: `u = c^s mod m`, затем разложение `u` по простым множителям `W` и восстановление степеней `x_i`.
- В интерфейсе и коде добавлено ограничение на рост параметров, чтобы генерация оставалась быстрой в учебной среде.

### Код Хэмминга

- Обязательный базовый вариант: `[7,4]`.
- Предполагается не более одной ошибки на кодовое слово.
- Поддерживается внесение искусственной ошибки в выбранную позицию.

## Чем учебная реализация отличается от промышленной криптографии

- Используются малые параметры, удобные для ручной проверки.
- Нет криптографического паддинга, защиты от атак по побочным каналам и безопасной генерации ключей промышленного уровня.
- Рюкзачные схемы приведены ради демонстрации математических идей, а не для реальной защиты данных.
- Код Хэмминга реализован в базовой лабораторной постановке `[7,4]`, без расширенных кодов и каскадирования.

## Как устроена архитектура проекта

Проект разделён на слои:

- `app/` — запуск приложения, главное окно, стили;
- `screens/` — отдельные экраны алгоритмов и общая навигация;
- `ui/` — reusable-виджеты и вспомогательные компоненты;
- `services/` — математическая логика алгоритмов;
- `models/` — dataclass-модели для ключей, шифртекстов и результатов;
- `utils/` — арифметика, валидация, кодеки, логирование;
- `tests/` — unit-тесты для сервисного слоя;
- `assets/` — папка под ресурсы интерфейса;
- `logs/` — журнал ошибок приложения.

Архитектура близка к MVC/MVVM-подобной: GUI не содержит математику, а сервисы не зависят от виджетов.

## Установка и запуск

### 1. Создать виртуальное окружение

```bash
python -m venv .venv
```

### 2. Активировать окружение

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Linux/macOS:

```bash
source .venv/bin/activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Запустить приложение

```bash
python main.py
```

## Как запускать приложение

- Откройте главную страницу.
- Выберите нужный модуль.
- Нажмите `Пример`, чтобы загрузить демонстрационные значения, или введите свои.
- Сгенерируйте ключи либо постройте код.
- Выполните шифрование/дешифрование или кодирование/исправление ошибки.
- Используйте кнопку `Показать шаги` для просмотра детального разбора.

## Тесты

Запуск unit-тестов:

```bash
python -m unittest discover -s tests -v
```

Тестами покрыты:

- RSA: `extended_gcd`, `mod_inverse`, `encrypt/decrypt`;
- Hamming: `encode`, `syndrome`, `correct`;
- рюкзачные схемы: `encrypt/decrypt` на учебных примерах.

## Источники, по которым выбрана постановка спорных мест

При выборе формулировок и учебных моделей использовались открытые источники:

- Qt for Python: `QStackedWidget`
- Ralph Merkle, *Secrecy, Authentication, and Public Key Systems*
- Merkle-Hellman и обзоры по knapsack cryptosystems
- A. Odlyzko, *The rise and fall of knapsack cryptosystems*
- учебные материалы по Hamming `[7,4]` и синдромному декодированию

Эти источники использовались для выбора прозрачной и математически последовательной учебной интерпретации, особенно для мультипликативного и обобщённых рюкзачных вариантов.
